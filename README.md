# 서울 국민평형 아파트 실거래가 전처리 및 지역별 통계 분석

데이터분석 부트캠프 미니 프로젝트 1입니다. 국토교통부 아파트 매매 실거래가 CSV를 Python으로 정리하고 MariaDB에 저장한 뒤, SQL로 연도·월·자치구별 거래 통계를 조회했습니다.

이번 프로젝트는 **Python과 SQL을 이용한 데이터 처리 및 집계**에 집중했습니다. 시각화와 심화 분석은 프로젝트 2, 회귀 예측은 프로젝트 3에서 다룰 예정입니다.

## 1. 분석 대상

- **자료 출처:** 국토교통부 실거래가 공개시스템의 서울 아파트 매매 CSV
- **기간:** 2020년 1월 ~ 2026년 11월 20일 수집분
- **지역:** 서울특별시 25개 자치구
- **면적:** 전용면적 83㎡ 이상 85㎡ 이하
- **거래금액 단위:** 만원 (일부 결과는 억원으로 환산)

2026년 자료는 11월 20일까지 확보한 자료이므로, 다른 연도의 연간 실적과 비교할 때 주의가 필요합니다.

## 2. 사용 도구

- Python, pandas, Jupyter Notebook
- MariaDB, SQL
- PyMySQL (Python과 MariaDB 연결)

## 3. 작업 과정

### CSV 통합 및 전처리

1. 2020~2026년 연도별 CSV 7개를 불러와 통합했습니다.
2. 전용면적 83~85㎡ 거래를 추출했습니다.
3. 거래금액의 쉼표를 제거하고 숫자형으로 변환했습니다.
4. `해제사유발생일`에 계약 해제일이 기록된 거래를 제외했습니다.
5. 중복 의심 거래와 IQR 기준 가격 이상치를 확인했습니다.
6. SQL 집계에 사용할 `계약월`, `자치구` 컬럼을 만들었습니다.

중복 의심 거래와 이상치 후보는 실제 거래일 가능성이 있어 임의로 삭제하지 않았습니다.

### MariaDB 저장 및 SQL 조회

- 데이터베이스: `realestate_project`
- 테이블: `apartment_sales`
- 주요 저장 항목: 계약월, 자치구, 시군구, 단지명, 전용면적, 층, 건축년도, 거래금액
- SQL 조회: 연도별·월별 거래건수 및 평균가격, 2025년 자치구별 거래건수 및 평균가격
- Python에서 계산한 월별·자치구별 거래건수와 SQL 조회 결과를 비교했습니다.

중위 거래가격은 pandas로 계산했습니다.

## 4. 주요 결과

| 처리 단계 | 거래건수 |
|---|---:|
| 연도별 CSV 7개 통합 | 153,428건 |
| 전용면적 83~85㎡ 추출 | 118,707건 |
| 계약 해제 거래 제외 | 5,624건 |
| 최종 분석 대상 | **113,083건** |

- 중복 의심 거래: **509건**
- 상세 정보가 동일한 거래: **349건**
- IQR 기준 이상치 후보: **5,420건**
- 2025년 분석 대상 거래: **26,105건**
- Python과 SQL의 월별 거래건수 및 2025년 자치구별 거래건수 교차 검증 완료

위 중복·이상치 수치는 **검사 결과**이며, 최종 분석 건수에서 추가로 제외한 건수가 아닙니다.

## 5. 파일 및 실행 방법

```text
realestate_project/
├── 01_seoul_apartment_project1_clean.ipynb
├── README.md
├── .gitignore
└── raw/                         # 원본 CSV (로컬 보관)
```

Notebook 실행에는 연도별 CSV와 로컬 MariaDB가 필요합니다. `raw/` 폴더에는 국토교통부에서 내려받은 연도별 CSV를 두고, Notebook의 `data_dir` 경로를 실제 폴더 위치에 맞게 설정해야 합니다.

Python 환경에서 Jupyter Notebook, pandas, PyMySQL을 설치합니다.

```bash
pip install notebook pandas pymysql
```

`realestate_project` 데이터베이스를 준비하고, `get_conn(database_name)` 함수를 제공하는 개인용 `db.py`를 연결할 수 있는 위치에 둡니다. DB 계정과 비밀번호는 공개 저장소에 올리지 않습니다. Notebook은 `DB_PASSWORD` 환경변수가 없으면 실행 시 비밀번호를 입력하도록 작성되어 있습니다. `db.py`의 실제 연결 설정은 사용하는 컴퓨터에 맞게 구성해야 합니다.

Notebook을 위에서 아래로 실행하면 CSV 통합, 전처리, DB 저장·건수 확인, SQL 통계 조회 순서로 진행됩니다. 이미 `apartment_sales` 테이블에 데이터가 들어 있다면 중복 저장을 방지하기 위해 삽입 단계를 건너뜁니다.

GitHub에서는 Notebook에 저장된 실행 결과를 확인할 수 있지만, 직접 재실행하려면 원본 데이터와 MariaDB 환경이 필요합니다.

## 6. 분석 시 주의사항

- 전용면적 83~85㎡ 거래만 포함하므로 서울 전체 아파트 시장을 대표하지는 않습니다.
- 계약 해제 거래는 제외했지만, 중복 의심 거래와 통계적 이상치 후보는 삭제하지 않았습니다.
- 평균 거래가격은 기간별·지역별 거래 구성의 영향을 받을 수 있습니다.
- 2026년 데이터는 수집 기간이 완결되지 않았습니다.
